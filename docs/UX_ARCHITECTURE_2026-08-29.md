# Устройство интерфейса пульта

29 августа 2026. Как устроен экран управления проектами агентства и почему
именно так.

---

## Чего не удалось сделать, и это надо сказать первым

Владелец попросил взять устройство интерфейса из нашей же консоли **Mosco**,
чтобы не выдумывать своё. **Прочитать её из рабочего окружения не удалось**,
и все три пути закрыты наглухо:

1. Подключение чужого репозитория запрещено: сессия уже держит репозитории
   владельца `contact715`, а консоль лежит в `Mosco-corp/console-next`.
2. Доступ к GitHub у сессии ограничен списком из одного `contact715/castells`.
3. Сеть наружу к живой консоли (`console-next-production.up.railway.app`)
   закрыта сетевым ограничителем.

Что известно о ней достоверно, из настроек Railway: это Next.js, собирается
`npx next build`, ходит в API по `NEXT_PUBLIC_API_URL`, вход через Google.
Ни разметки, ни цветов, ни шрифтов оттуда я не видел.

**Поэтому взято только то, что владелец назвал словами: сайдбар и верхняя
панель.** Всё остальное — цвета, шрифты, размеры — вынесено в один файл
`services/lib/theme.mjs`, чтобы подмена на московское свелась к правке
значений, без трогания разметки и поведения.

Чтобы это закрыть, нужен один из двух ходов:
- открыть сессию, где исходным репозиторием стоит `Mosco-corp/console-next`;
- прислать сюда файлы оболочки консоли (или снимки экрана).

## Устройство

```
┌──────────────┬─────────────────────────────────────────┐
│  Castells    │  Пульт · <текущий раздел>   [проект ▾] │  ← верхняя панель
├──────────────┼─────────────────────────────────────────┤
│ ОБЗОР        │                                         │
│  Все проекты │                                         │
│  Чего нет    │            экран                        │
│  Каталог     │                                         │
│              │                                         │
│ ПРОЕКТЫ      │                                         │
│  ● Castells  │                                         │
│  ● AAA Bro…  │                                         │
│  ● HP Tint…  │                                         │
│  ● Roman's   │                                         │
└──────────────┴─────────────────────────────────────────┘
   сайдбар
```

**Сайдбар** — куда идти. Две группы: общие экраны и проекты. У каждого
проекта точка состояния и счётчик открытых доступов, поэтому список сам по
себе уже отчёт: видно, где пусто, не открывая.

**Верхняя панель** — где я сейчас и с чем работаю. Слева хлебная крошка,
справа выбор проекта и отметка времени сборки. Панель липкая: при длинной
странице всегда видно, чей это проект.

**Экран** — один за раз.

## Экраны

| Адрес | Экран | Отвечает на вопрос |
|---|---|---|
| `#/overview` | Все проекты | Где мы вообще? |
| `#/access` | Чего не хватает | Что просить и у кого? |
| `#/catalog` | Каталог услуг | Что мы умеем и чего не делали? |
| `#/p/<id>` | Проект | Что с этим клиентом? |

Экран проекта собран из четырёх блоков в порядке важности: **услуги** (что
делаем), **стадии** цикла SEO, **доступы**, **ежемесячный отчёт**.

## Решения, которые стоит знать

**Переходы через решётку (`#/…`), а не через адреса сервера.** У пульта два
потребителя: сервер на Railway и одиночный файл, который открывают локально
или публикуют. Решётка работает одинаково в обоих случаях, серверные
маршруты — только в первом.

**Первый экран видим в разметке, остальные скрыты.** Если скрыть все и
положиться на скрипт, то при выключенных скриптах или до их загрузки
страница пуста, и это выглядит как поломка, хотя данные уже пришли. Ошибка
была допущена при первой сборке оболочки и поймана самопроверкой.

**Никаких полосок «готовность в процентах».** Оставшееся упирается в чужие
решения; проценты создавали бы ощущение движения там, где его нет.

**Цвет состояния отделён от акцентного.** Акцент — бирюзовый, им отмечены
переходы и текущий раздел. Зелёный, красный и янтарный означают только
состояние (открыто, закрыто, ждёт) и больше нигде не используются.

**Три состояния темы, а не два.** Явный выбор ставит `data-theme` на корне, а
настройка «как в системе» не ставит ничего — тогда светлую от тёмной отличает
только `prefers-color-scheme`. Поэтому тёмная объявлена дважды, иначе у
части людей получился бы тёмный текст на тёмном фоне.

## Где что лежит

```
services/
  lib/theme.mjs     цвета, шрифты, размеры — ЕДИНСТВЕННОЕ место
  lib/shell.mjs     оболочка: сайдбар, панель, переходы
  dashboard.mjs     экраны и их содержимое
  server.mjs        отдаёт всё это по HTTP на Railway
```

Разделение не для красоты: оболочка не знает про доступы и отчёты, поэтому её
можно переодеть под Mosco, не задев данные. И наоборот — новый экран
добавляется в `dashboard.mjs`, не трогая оболочку.
