## Что сделано в этой смене

**1. Меню.** На сайте было три независимых списка разделов, и все три говорили
разное: шапка знала пять разделов, подвал семь, разметка для поисковых роботов
восемь. Страницу команды и страницу Roseville не показывало ни одно из трёх:
ссылка на них была ровно на одной странице сайта из семидесяти шести.

Список теперь один, в `data/navigation.ts`. Его читают шапка, подвал и
генератор статических страниц. В шапке семь пунктов, восьмой не влезает по
замеру: при ширине окна 1024 под пункты остаётся около 470 точек, семь
занимают 453. Журнал, команда и Roseville живут в подвале.

`/learn` стала общим входом для чтения: сверху ответы на вопросы, ниже журнал.

**2. Сетки.** Шесть сеток на сайте были объявлены двенадцатиколоночными с
промежутком в 96 точек. У двенадцати колонок одиннадцать промежутков, это
1056 точек только на пустоту при ширине ряда 961. Браузер считал ширину всех
двенадцати колонок нулевой, содержимое вылезало наружу, главная прокручивалась
вбок. Все шесть на деле двухколоночные, переписаны на две дорожки.

**3. Пробелы перед переносом строки.** Одиннадцать мест, где текст стоял
вплотную к `<br />`. На экране перенос виден, читалка экрана склеивает слова:
заголовок хаба ниш читался как «Industries wework with».

**4. Самопроверка встала в сборку.** Проверка генератора страниц существовала,
но её никто не запускал, поэтому она молча краснела на слишком длинном
описании страницы Roseville. Теперь это первый шаг сборки, 0,06 секунды,
красное останавливает выкатку. Проверок 29, все зелёные.

## Что известно и не сделано

**Заголовки вкладки при переходах — ЗАКРЫТО 24 августа, вечер.** Раньше при
переходе по меню заголовок вкладки, описание и канонический адрес оставались от
первой открытой страницы: человек доходил до контактов, а страница объявляла
себя главной. Теперь шаблоны заголовков лежат в `scripts/page-meta.mjs` и их
читают обе стороны — генератор готового HTML и приложение в браузере. Второй
копии нет намеренно.

Доказано двумя способами: `npm run check:meta` сверяет все 75 готовых страниц
по трём тегам (75 из 75), и прогон по живому сайту сравнил 17 адресов всех
видов, включая выдуманный — тот честно отвечает «страница не найдена».

**Девять ошибок типов** в проекте, все существовали до этой смены:
`AllIndustriesPage`, `CaseStudyDetail` (две), `Button`, `Input`,
`SchemaMarkup` (три), `WillChangeManager`.

## Что ждёт владельца

Это не делается из сессии, нужен доступ:

1. **Формы не доставляют заявки.** Нужен ключ `RESEND_API_KEY` в настройках
   Vercel и подтверждение домена в почтовом сервисе. Без этого письмо не
   уйдёт даже с ключом. Пока форма честно отвечает «напишите в WhatsApp».
2. **Аналитики нет никакой.** Ни счётчика, ни Search Console. О посетителях
   не известно ничего.
3. **Отзывов на сайте ноль.** Нужны пять сообщений клиентам.
4. **Google Business Profile не заведён.**

## Как сайт устроен, коротко

React и Vite, выкладка на Vercel, боевой адрес `https://www.castells.media`.
Пуш в `main` запускает выкатку сам.

- `data/navigation.ts` — разделы сайта, один источник для трёх меню
- `scripts/page-meta.mjs` — заголовки и описания страниц
- `scripts/prerender-pages.mjs` — собирает статический HTML для каждого адреса,
  карту сайта, robots.txt и страницу 404. Здесь же 29 самопроверок
- `scripts/inline-css.mjs` — вшивает стили в HTML
- `index.css` — цвета и шрифты в блоке `@theme`

Проверить всё разом:

```bash
npm run check
```

Собрать (самопроверка идёт первым шагом и блокирует сборку при красном):

```bash
npm run build
```

## Договорённости, которые не выводятся из кода

- Локальные серверы не поднимаем: владелец смотрит изменения сразу на боевом
  сайте. Проверка в браузере делается на `https://www.castells.media`.
- Ничего непроверенного на сайт не пишем. Ни рейтингов, ни процентов, ни
  сроков работы, которые нельзя показать. Каждое число на сайте — это наша
  же опубликованная цена.
- Репозиторий `castells-calls` — чужой боевой, только на чтение.
