# ТЗ для браузерного агента: подключить измерение сайта castells.media

29 августа 2026. Документ самодостаточный: у исполнителя нет доступа к нашему
репозиторию, поэтому все нужные значения выписаны прямо здесь.

---

## Контекст

Сайт маркетингового агентства. Собирается из репозитория, выкатывается на
Vercel. Сегодня на нём **нет ни счётчика посещений, ни Search Console**: мы не
знаем, приходит ли на сайт хоть один человек. Задача — закрыть это.

**Данные, которые понадобятся:**

| Что | Значение |
|---|---|
| Домен | `castells.media` |
| Рабочий адрес сайта | `https://www.castells.media` |
| Карта сайта | `https://www.castells.media/sitemap.xml` (87 адресов) |
| Юридическое лицо | Castells Media Inc. |
| Телефон | +1 (916) 619-6006 |
| Почта | contact@castells.media |
| Улица | 1298 Antelope Creek Drive |
| Город, штат | Roseville, California |
| Хостинг | Vercel, проект `castells`, команда «Dmitrii's projects» |

**Важная особенность, из-за которой легко всё сделать зря.** Адрес без `www`
(`castells.media`) отвечает перенаправлением 308 на адрес с `www`
(`www.castells.media`). То есть настоящий сайт живёт на `www`. Если завести в
Search Console свойство типа «префикс адреса» на версию без `www`, оно будет
показывать пусто, и это будет выглядеть как «сайт не индексируется», хотя
причина в выборе свойства.

**Индекс почты не проверен из нашей среды**, поэтому пункты про DNS написаны
так, чтобы исполнитель сначала посмотрел, что там есть, а не действовал
вслепую.

## Задача 1. Google Search Console — свойство домена

**Зачем.** Без неё мы не видим, по каким запросам находят сайт, какие страницы
Google проиндексировал и что он считает ошибкой. Это главный пробел.

**Что сделать.**

1. Открыть <https://search.google.com/search-console>, войти под рабочим
   аккаунтом Google владельца.
2. Добавить ресурс, выбрать тип **«Ресурс-домен» (Domain property)**, а не
   «Префикс URL». Ввести `castells.media` без протокола и без `www`.

   Почему именно домен: такой ресурс покрывает сразу `castells.media`,
   `www.castells.media`, оба протокола и все поддомены, включая будущий
   `academy.castells.media`. Вариант «префикс URL» покроет что-то одно, и с
   нашим перенаправлением легко выбрать не то.
3. Google покажет **запись TXT** для подтверждения. Скопировать её целиком.
4. Зайти в панель управления DNS домена `castells.media` (регистратор — у
   владельца; из нашей среды проверить не удалось, DNS-запросы наружу
   заблокированы). Добавить запись:
   - тип: `TXT`
   - имя/хост: `@` (корень домена)
   - значение: строка, которую выдал Google
   - TTL: оставить по умолчанию
5. **Не удалять существующие записи TXT.** Если на корне уже есть TXT
   (например, SPF для почты) — добавить новую запись рядом, а не заменить
   существующую. Замена SPF ломает доставку почты.
6. Вернуться в Search Console и нажать «Подтвердить». Если не сработало —
   подождать 10–15 минут, DNS обновляется не мгновенно, и повторить.

**Готово, когда.** В Search Console ресурс `castells.media` отмечен как
подтверждённый.

## Задача 2. Отдать карту сайта

**Зачем.** Карта сайта — это список всех страниц. Без неё Google находит
страницы медленнее.

**Что сделать.** В подтверждённом ресурсе: раздел «Файлы Sitemap» →
добавить `sitemap.xml` → отправить.

Если поле требует полный адрес, вписать
`https://www.castells.media/sitemap.xml`.

**Готово, когда.** Статус карты — «Успешно», и указано **87** обнаруженных
адресов. Если число заметно меньше — записать, какое, и сообщить: это признак
проблемы на нашей стороне, которую будем чинить в коде.

## Задача 3. Проверить, как Google видит сайт

**Зачем.** Один раз посмотреть глазами на то, что мы до сих пор могли только
предполагать.

**Что сделать** (после подтверждения ресурса; данные появятся не сразу, часть
разделов заполнится за 1–3 дня):

1. Раздел «Проверка URL», ввести `https://www.castells.media/`.
   Записать: страница в индексе или нет.
2. Повторить для трёх адресов:
   - `https://www.castells.media/services/meta-ads`
   - `https://www.castells.media/industries/hvac-systems`
   - `https://www.castells.media/academy`
3. Раздел «Индексирование страниц»: записать, сколько страниц
   проиндексировано и сколько исключено, и по каким причинам исключены (там
   будет список причин с числами).

**Что вернуть.** Простой список: адрес → в индексе или нет. Плюс числа из
раздела «Индексирование страниц». Ничего не чинить — это наша работа.

## Задача 4. Bing Webmaster Tools

**Зачем.** Отдельная поисковая система, полностью бесплатно, и по нашим
проверкам Bing уже видит часть сайта — то есть отдача будет сразу. Плюс на
данные Bing опирается поиск внутри некоторых ИИ-ассистентов.

**Что сделать.**

1. Открыть <https://www.bing.com/webmasters>, войти.
2. Выбрать импорт из Google Search Console (кнопка «Import from GSC») — это
   быстрее ручного подтверждения и переносит уже подтверждённые права.
   Если импорт не срабатывает, добавить сайт `https://www.castells.media`
   вручную и подтвердить записью TXT в DNS (правила те же, что в задаче 1:
   существующие TXT не трогать).
3. Отправить карту сайта `https://www.castells.media/sitemap.xml`.

**Готово, когда.** Сайт в Bing Webmaster Tools подтверждён, карта принята.

## Задача 5. Google Analytics — только создать, не встраивать

**Зачем.** Сейчас счётчика нет вообще: сколько людей приходит на сайт,
неизвестно.

**Что сделать.**

1. Открыть <https://analytics.google.com>, создать аккаунт (если его нет) и
   **ресурс GA4** для `www.castells.media`.
2. Часовой пояс: **America/Los_Angeles**. Валюта: доллар США.
3. Создать поток данных типа «Веб», адрес `https://www.castells.media`,
   имя потока — `castells.media`.
4. Скопировать **идентификатор потока данных** — строка вида `G-XXXXXXXXXX`.

**Что вернуть.** Только эту строку `G-...`.

**Чего НЕ делать.** Не вставлять код счётчика через Google Tag Manager и не
пытаться добавить его на сайт. Сайт собирается из репозитория; счётчик,
вставленный снаружи, будет затёрт при следующей выкатке. Встроим в код мы.

## Задача 6. Профиль Google Business

**Зачем.** Для местного поиска это половина дела: человек, у которого сломался
кондиционер, ищет в картах. У нас профиля нет.

**Важно прочитать до начала.** Адрес компании — жилой, и в реестре штата он
записан с номером квартиры. Поэтому:

- при выборе типа бизнеса указать, что **обслуживание идёт на выезде**
  (service-area business);
- **адрес скрыть** от публичного показа, оставив только зоны обслуживания.
  Google это прямо поддерживает: адрес нужен для подтверждения, но
  показывать его не обязательно;
- **точный почтовый индекс и номер квартиры уточнить у владельца.** В наших
  данных индекс не заполнен, а по публичному реестру компаний он выглядит как
  95678 с номером квартиры — но это сведения со стороны, и вписывать их без
  подтверждения владельца нельзя.

**Что сделать.**

1. Открыть <https://business.google.com>, создать профиль.
2. Название: **Castells Media** (ровно так, без добавок вроде «Inc», без
   города и без ключевых слов — за приписки Google наказывает).
3. Основная категория: **Marketing agency**.
4. Телефон: +1 (916) 619-6006. Сайт: `https://www.castells.media`.
5. Зоны обслуживания: Roseville, Sacramento и окрестности.
6. Запустить подтверждение и **остановиться**: способ подтверждения (открытка,
   видео, телефон) выбирает владелец, а открытка идёт неделями.

**Что вернуть.** На каком шаге остановились и какой способ подтверждения
предлагает Google.

## Задача 7. Доставка писем с формы заявки (Resend)

**Зачем.** Форма на сайте сейчас не отправляет письмо: она честно предлагает
написать в WhatsApp. Код готов и ждёт ключ.

**Что сделать.**

1. Зарегистрироваться на <https://resend.com> (бесплатного тарифа хватает для
   начала).
2. Раздел «Domains» → добавить домен `castells.media`.
3. Resend выдаст набор записей DNS (обычно DKIM типа TXT или CNAME и запись
   MX для обратного адреса). Добавить их в DNS домена.
   **Те же правила: существующие записи не удалять**, особенно MX и SPF, если
   на домене уже работает почта. Если возникает конфликт с существующей
   записью — остановиться и спросить владельца, а не перезаписывать.
4. Дождаться, когда домен в Resend станет «Verified».
5. Создать ключ API (раздел «API Keys»), права на отправку.
6. Открыть <https://vercel.com>, команда «Dmitrii's projects», проект
   `castells` → Settings → Environment Variables. Добавить:
   - имя: `RESEND_API_KEY`
   - значение: созданный ключ
   - окружения: отметить все три (Production, Preview, Development)
7. **Не нажимать Redeploy.** Скажите нам — мы выкатим и проверим, что форма
   действительно доставляет письмо. Проверка на живом сайте наша.

**Что вернуть.** Подтверждение, что домен «Verified» и переменная добавлена.
**Сам ключ не присылать текстом в переписку** — он уже в Vercel, этого
достаточно.

## Задача 8. Поддомен академии

**Зачем.** `academy.castells.media` задуман как адрес раздела академии. Сейчас
записи DNS для него нет, поддомен не работает.

**Что сделать.**

1. Vercel → проект `castells` → Settings → Domains → добавить
   `academy.castells.media`.
2. Vercel покажет нужную запись DNS (обычно CNAME на `cname.vercel-dns.com`).
   Добавить её в DNS домена с именем `academy`.
3. Дождаться, пока Vercel отметит домен как настроенный.

**Готово, когда.** `https://academy.castells.media` открывается и приводит на
раздел академии.

## Чего делать нельзя

- **Не удалять и не перезаписывать существующие записи DNS.** Только
  добавлять. Затёртая запись SPF или MX ломает почту домена, и это заметят не
  сразу.
- **Не менять ничего в самом сайте**: ни через Vercel, ни через Tag Manager.
  Сайт собирается из репозитория, любые правки снаружи будут затёрты.
- **Не нажимать Redeploy** в Vercel.
- **Не придумывать данные.** Если не хватает индекса, номера квартиры или
  чего-то ещё — остановиться и спросить. Неверный адрес в профиле Google
  потом вычищается неделями.
- **Не публиковать домашний адрес** в профиле Google Business.
- **Не присылать ключи и пароли текстом** в переписку.
